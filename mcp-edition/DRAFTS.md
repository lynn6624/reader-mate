# 管理员草稿编辑与快捷设章（B线第一步）

管理员打开书后，点「草稿」进入同一阅读器的草稿预览。手机上的按钮位于左下角。选中文字后点「编辑草稿」，修改替换框，停止输入约800毫秒后自动保存；留空可删除。看到「已保存」后点完成。也可以在正式版选中文字后直接进入编辑；如已有改过的草稿，会先打开它并要求重新选择，避免混用正式版与草稿的位置。

刷新后默认仍打开正式版，再点「草稿」继续编辑同一本书；草稿定位在最近一次编辑附近。顶部显示草稿版本、编辑次数和章节待核对数量，点「返回正式版」回到正常阅读。编辑请求失败时保留输入，支持重试；发生版本冲突时先复制输入，关闭后重新打开草稿核对，不自动覆盖他处更新。未保存输入离页时由浏览器提示，切后台会尝试补保存，但不能保证断网或浏览器强杀前尚未提交的输入可恢复。

## 章节

管理员选中标题，点「设为章节」，可修改章名和上级章节。正式版此操作只更新原有 navigation 目录元数据，不改正文；草稿模式则只保存草稿目录。打开目录后，点行旁「改」「删」即可管理；删除父项时子项提升一级。仍保留原高级 JSON 导入/导出、预览、校验能力，草稿模式用快捷入口管理自己的目录。

草稿文字编辑后，后方章节按明确编辑操作调整 UTF-16 位置并重新校验。若选区覆盖某章节起点，则保留完整目录项为「待重新定位」，不猜位置；重新选择正文、点「设为章节」，在恢复下拉框中选该待核对项，可保留原目录 ID 修复。已存在草稿建立后，正式版目录的后续修改不会自动合入该草稿，防止覆盖人工选择。

## 数据和保护

新增 data/drafts/<SHA256书名>.json，一书一份，schema_version=1。记录 name、base_revision（原文件SHA）、revision、operations（每次的稳定请求ID、起止UTF-16位置、原文before、替换after、提交者、时间及请求摘要）、items（草稿目录）、chapter_issues、cursor_offset。操作坐标属于每次修改前的草稿版本，不是正式原书坐标。读取时按顺序严格重放原文匹配，任何歧义或损坏均拒绝，不自动套到其他位置。后续正式发布仍需单独迁移全部原书锚点，本阶段不做。

草稿完整读改写受现有服务线程锁和跨进程文件锁保护，带 expected_revision 乐观校验；固定 request_id 的同一编辑可安全重试，不重复删除。写入使用唯一临时文件、flush/fsync及一次原子替换，失败保留前一草稿；进程重启可从完整记录继续。没有在一个保存中切换正文和其他文件，因此不宣称已完成未来的多文件发布事务。任意硬断电恢复未实测。

原书变化返回409并保留旧草稿；损坏草稿返回503并保留文件。原 TXT、进度、划线、批注、身份和分类不参与草稿写入。草稿中禁止保存正式阅读进度或添加正式划线，暂时禁用全书搜索和朗读；字体、滚动、复制、窗口加载和目录跳转复用原阅读器。退出后正式阅读能力恢复。

权限严格沿用 user 管理员及既有鉴权；新人类和 Agent 不能直接读写管理员草稿或正式目录。不可用 Kindle 配对Cookie编辑。本次不安装或改造 Kindle 扩展，轻量页面仍使用原生DOM。

资源限制：原文件最多8MB，解码正文最多200万UTF-16单位，每次替换前后均最多4000单位，每本草稿最多200次文字编辑，草稿JSON最多4MB，编辑请求最多64KB，目录仍8000项/8层。浏览器每次最多返回60000单位窗口，目录分页最多500项；转换和编辑不并发全库扫描，不增加依赖或常驻服务。超过限制明确拒绝并保留已有草稿。这是第一阶段的资源上限，不能当作无限编辑器使用。

## 内部API

- POST /api/draft/start：name、book_revision；可选 view_offset。建立或打开草稿。
- GET /api/draft?name=...&offset=...：管理员读取一个草稿窗口，返回 draft_revision、base book_revision、text_base、total_units、chapter_index、chapter_issues等。
- POST /api/draft/edit：name、base_revision、expected_revision、request_id、start、end、quote、replacement。写入作者由服务端确定为管理员。
- GET /api/draft/navigation?name=...&offset=0&limit=200：草稿目录分页。
- POST /api/draft/chapter：name、base_revision、expected_revision、action=upsert|delete；upsert带 start/end/quote/title/parent_id，修改或删除带 id；可选 resolve_issue_id 恢复待核对项。
- POST /api/chapter：相同章节参数，带 book_revision 和目录 expected_revision，更新现有正式目录元数据。保存后在锁外追加既有审计记录。

MCP工具仍12个，Schema、只读调用指南和进度协议不变。本阶段没有开放 Agent 修订工具。

## 部署与回退

新增 core/book_drafts.py 和 core/web/editor.js，更新 core/reader_server.py、web/reader.html。页面由现有服务内联 editor.js，部署要一起带上这两份新文件。无需数据库迁移；打开草稿时按需建立自己的元数据，原目录schema仍1。

备份现有代码和数据后，停服务、替换上述4文件、重启并核验。个人昵称只保留于私有部署页面，公开版不内置个人昵称。回退只恢复旧代码，保留当前 data/drafts 和 navigation 目录，不恢复旧进度/批注/身份快照；旧版阅读器暂时不显示草稿，重新部署兼容版本后可继续。正式目录修正仍兼容旧版高级入口。

验收 selftest-drafts.py 使用隔离书籍覆盖真实HTTP/CAS/失败/重试/重启、emoji、章节调整和问题恢复、200项操作上限及有界窗口；默认再用Playwright/Chrome验证桌面与手机选区自动保存及刷新续改。--no-browser用于Linux。现有导航/EPUB、保全、成员、MCP、正式书架及进度界面须回归。真实手机和实际书籍可继续由管理员试用。
