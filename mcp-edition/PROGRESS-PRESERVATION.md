# 阅读进度保全与恢复

本修复补齐交接稿阶段 0 的阅读进度存储保护。只修改 MCP 版进度读写；书籍 ID、身份 ID、UTF-16 坐标、阅读进度接口及原 12 个 MCP 工具保持兼容。

## 正常保存

- 旧 `books[书名] = 进度` 在内存中视为 user 的记录；新 `books[书名] = {身份:进度}` 保留原身份字符串和所有记录，不按当前成员名单过滤、不清洗历史 ID。成员名恰好为 offset/updated 等字段名时，字典值仍按成员记录解释。
- 普通读取不写盘。无法解释的容器、重复键、无效 JSON/非有限数字会返回 503，保留原文件；无法确定的混合形状拒绝自动转换。
- 首次写入前，将原始字节（包括 BOM、缩进和历史字段）备份到私有 `data/progress-backups/legacy-<SHA256>.json`。目录 0700、文件 0600，绝不能提交 Git 或打入公开发布包。首次成功后写入 `preservation_version:1`，后续普通保存不重复复制整库。
- 完整 HTTP 读改写和启动初始化使用 `progress.json.lock`，复用现有跨进程锁。`load_progress()` 返回带原文件摘要的快照；直接调用 `save_progress()` 也会在提交时比较摘要，旧快照返回 409，必须重读再操作。原有每身份 expected_revision 和正文 book_revision 检查继续有效。
- 正本写入唯一临时文件，flush/fsync 后一次原子替换；失败时原正本保留、临时文件清理。更新当前成员保留其自定义扩展字段。备份不完整或已存在但内容不符时拒绝写入。

所有线上写入者必须升级至本协议；任意旧脚本或外部编辑器直接写文件不能由此锁保护。章节重算工具仍要求停 Web 后离线执行。不要把普通原子替换称为未来发布正文与多份数据的整体事务。

## 正本与 Markdown 镜像

`data/progress.json` 是唯一正本，`data/阅读进度.md` 是可重建展示。保存 JSON 后镜像失败，API 仍返回成功和真实的新 revision，并给出 `mirror_updated:false`；日志仅说明镜像未更新，不包含进度、原文或凭据。不能因为镜像失败恢复旧 JSON，也不要用旧 expected_revision 反复保存。

下次正常保存会重新生成镜像。管理员也可在实际部署的 core 目录、以服务用户运行：

```sh
python -c 'import reader_server as r; raise SystemExit(0 if r.rebuild_progress_mirror() else 1)'
```

命令持有同一锁，只从当前正本生成 Markdown，不修改正本或续读位置。遇到损坏正本会报错并保留原件。提交后、镜像前进程中断也按此恢复；这是可恢复的展示落后，不代表正本提交失败。

## 症状 → 检查 → 修复

| 症状 | 检查 | 修复 |
|---|---|---|
| 读取/保存返回 503 | 正本是否为完整 JSON、有重复键或异常结构；服务用户的目录和文件权限 | 停止相关写入，先私下备份当前原件，再对照可信备份做人工核对；不能直接用旧整库盖掉后来进度 |
| 提示“进度已更新”或返回 409 | 另一设备/进程是否保存了进度；调用方是否复用了旧快照/expected_revision | 重新读取当前进度，再明确提交所需位置；不盲目覆盖 |
| 首次兼容保存失败 | 备份目录权限、磁盘余量；同摘要备份是否与原始字节一致 | 保留当前正本及异常备份，核实后修复权限/存储或错误备份；失败后可安全重读重试 |
| API 保存成功但 Markdown 未更新 | 响应 mirror_updated、镜像路径及权限 | 修好权限后运行上述重建命令；不要回退已保存的 revision |
| 旧身份仍出现在历史进度 | 原记录的稳定 ID 与撤销状态 | 这是保留历史的预期行为，不重新分配 ID、不并入 user |

已丢失的历史只可从可信备份恢复，不推测身份、位置或阅读时间。此代码修复不会自动找回上线前已被覆盖的记录。

## 部署与回退

先备份现有代码和数据并核对 main 基线。暂停相关写入服务，替换 MCP 版 `core/reader_server.py`（同目录的既有 member_store.py 保留），重启，使用隔离样例验收后只读核验现有进度。无需部署时批量迁移，不需要新依赖、服务、后台任务或全书扫描。本次 PR 未执行生产部署。

停止服务时可保留当前数据、切换到兼容此存储协议的代码；不要恢复旧进度快照。退回有损 ID 规范化/损坏文件兜底为空库的旧实现，会重新引入丢数据风险，优先修复前进。存在已保全的历史 ID 或新记录时，不能宣称旧写入器安全兼容。

隔离验收覆盖了提交前后进程终止与恢复，未验证任意断电和磁盘/文件系统故障；目录持久化及多文件整体事务不在本阶段保证内。已有书籍删除流程仍跨多个文件，不把它当作未来正文发布方案。

测试命令与完整接手清单见 [TAKEOVER-20261025.md](TAKEOVER-20261025.md)。下一功能阶段仍是 Agent 建议与独立校对进度，随后才做审批和可回滚发布。
