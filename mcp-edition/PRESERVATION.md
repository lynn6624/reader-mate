# 历史批注与稳定身份保全

本修复独立于新成员管理和协作校对，继续使用原TXT、身份令牌、阅读进度和notes.json，不建立第二套身份系统。

## 已修复的实际问题

旧的 `_norm_highlight` 只接受评论who=user/ai，其他历史值被跳过；后续任意批注保存都会把经过过滤的整库写回。旧代码还会裁剪历史评论、丢弃扩展字段，以及把缺少owner/author_id的划线猜成user。

现在合法历史评论的who、身份字符串、原文和扩展字段均保留，不依赖当前身份名单。已撤销凭据的身份历史仍可按原ID读取。新划线和新评论仍由服务端已认证身份赋予author_id，客户端自称或传入author_id不能改变归属。

显式author_id优先；旧owner、who=user、who=ai/name或历史身份值作为兼容来源。无任何来源时author_id=null、author_status=unknown，页面显示“历史作者未知”，不允许借此冒认编辑/删除。author_status=recorded只表示记录有身份来源，不表示该凭据当前有效或具有管理权限。颜色和昵称不参与鉴权。

## 存储及失败处理

notes.json保持version=2，新增兼容标记preservation_version=1。普通读取不写文件；第一次修改前，原始字节保存在 `core/data/notes-backups/legacy-<SHA256>.json`，目录0700、备份0600。后续正常修改不反复复制全文。兼容标记在成功保存时写入，未知合法字段保留。

Web原有线程锁保护完整读改写；保存再使用进程提交锁和读取快照摘要校验。Linux使用flock，Windows使用标准库msvcrt；旧快照返回409，写入使用唯一临时文件、fsync和原子替换。锁文件在data目录内，无新常驻服务或生产依赖。所有服务和维护程序应沿用统一写入协议；未遵循协议的外部编辑器不在并发保证内。

损坏JSON、重复键、非法结构或不能解释的坐标/作者字段不会退回空库：notes读写返回503，原文件保留，阅读正文继续可用，前端明确提示。处理前先私下备份当前原文件，核验可信备份和差异；不能用旧整库覆盖后来新增评论。若首次备份不完整或备份校验失败，写入暂停并要求管理员核查；本轮不宣称已经验证任意硬断电后的自动恢复。

不修改原TXT、UTF-16偏移、进度revision、分类或身份ID。没有数据库迁移命令，不批量重写书籍；兼容补充字段只随正常notes修改保存。身份令牌管理仍使用原配置，保留user系统身份；删除user返回409，其他成员的凭据仍按原管理员权限撤销，历史notes不删除。

## HTTP 与 MCP 兼容

原GET notes/annotations及新增评论接口保持调用方式。编辑／删除评论可增加annotation_id，服务端优先按稳定ID找目标；列表序号变化也不误操作另一条，目标消失或ID歧义返回409。index保留兼容旧客户端，新前端总是发送稳定ID。旧的仅index客户端仍采用原位置语义，建议升级前端。

```json
{"name":"example.txt","id":"h_example","annotation_id":"a_example","index":1,"text":"修改后的正文"}
```

上述为POST /api/notes/comment/edit；删除使用 /api/notes/comment/delete，省略text。ID和所有权由服务端校验，知道ID不等于有权修改。保留现有12个MCP工具和输入Schema，没有新增工具；旧MCP连接无需因本修复重建。

## 实证与测试

- 隔离样例复现旧代码把2条评论读成1条，以及无作者划线被归user；修复后保留自定义、未知和已撤销身份、长旧评论、额外字段及稳定ID。
- 测试首次兼容备份与原字节一致、陈旧快照拒绝、替换失败原库不变且可重试、两个进程竞争后的安全重读，以及并发HTTP请求不覆盖。
- 列表前一项删除后，以旧index和正确annotation_id编辑/删除后项仍命中原记录；重复删除不影响后来追加的评论。普通成员不能伪造作者或编辑他人/未知作者的内容。
- 手机/桌面显示未知作者，历史who按文本转义、CSS角色取固定枚举；损坏notes出现明确提示，恢复后可继续读取。正常读取和目录操作不写进度。
- 真实HTTP/MCP、旧进度、目录/EPUB、浏览器批注回归通过。可选Kindle测试验证有效设备Cookie遇到显式错误身份令牌仍拒绝，不降级user；扩展没有因此安装到生产。
- Linux隔离测试通过，合成样本观测单进程最大RSS33588KiB；不是并发合计或大数据集内存上限。真实存储只在服务器原地读，旧字段逐项保全及可信备份评论对照通过，未导出私人内容。

开发验收可运行 `python core/selftest-preservation.py --no-browser`；手机/桌面浏览器部分需要开发环境Playwright/Chrome，生产不安装这些依赖。

## 上线与恢复

先在临时书库验收、记录旧代码SHA、备份代码及数据。替换代码时暂停相关服务并验证原TXT哈希、notes/progress/library/identities字节不变；重新启动后只读验证两类MCP入口及身份管理状态。个人部署昵称属于本地差异，公开版继续显示真实ID。

回滚不得恢复旧数据快照。若升级后已出现新的或保全后的notes，旧的有损规范化代码可能再次丢弃记录，因此自动回滚入口应拒绝恢复它；保留当前数据和修复，采用修复前进或经验证的兼容代码。只有确认notes仍与升级前相同，才可仅恢复原代码。不永久复制整本书，也不把恢复材料加入Git。

PR4尚未实施；昵称、成员类型、多凭据及身份/凭据事务另行交付。当前云端启动仍要求有效user配置，缺失时应从可信私有备份核对恢复；不要通过关闭鉴权或重建全部身份解决。代理Host/端口和示例域名需按部署文档配置，不应关闭Host保护。
