# ReaderMate MCP 版（云端共读）

这是小书桌的 **MCP 版**源码包：沿用原 TXT 阅读器，增加云端多人共读、结构化划线和批注 MCP，以及身份令牌管理页。仓库原有 `core/` 桌面版保持独立；本目录可单独部署。

2026-10-21：书库按文学小说、网络文学、随笔与纪实、科普与工具、人文社科、待分类六组显示，默认折叠，可记住展开状态；搜索跨组并展开结果。主人上传前必选分类，批量可统一设置或逐本调整，卡片下拉框可事后修改。旧书与未传分类的旧导入调用归待分类。分类保存在原 `data/library.json`，不移动 TXT、不改变书名标识或阅读数据；人工分类不会被自动建议覆盖。MCP `list_books({})` 兼容原调用，增加可选 `category` 参数（如 `{"category":"humanities"}`），并返回六组名称与数量。分类 ID 见调用参考 TXT。普通身份只能浏览分类。

第六组 `humanities`（人文社科）用于哲学、心理学、社会学、性别研究、传播学、思想史等理论及研究著作。「随笔与纪实」保留 `nonfiction` ID。新增分组及名称调整不迁移或自动重分现有书籍，用户可自行调整。

- `core/reader_server.py` 与 `core/web/reader.html`：书库、阅读进度、多人划线和批注。
- Kindle 阅读是**单独安装的可选扩展**。默认源码包不含扩展；安装匹配版本的 Kindle 包后，Web 服务才提供配对链接与可撤销设备会话。配对后沿用主人 `user` 的进度，不向设备交付主人令牌。
- `core/mcp_server.py`：Streamable HTTP MCP，按身份令牌读取和写入共读数据。
- `core/MCP工具标准调用参考_只读.txt`：MCP 工具的标准调用顺序；部署时复制一份到共享书库。Agent 可先调用 `get_calling_guide({})`，`read_book` 的独立 `reminder` 字段会提示读完后调用 `update_progress` 保存位置。
- `token-mcp/`：管理员创建身份令牌的网页；创建成功时同时显示通用 MCP URL。
- `deploy/`：systemd、代理和密钥初始化示例；步骤见 [DEPLOY.md](DEPLOY.md)。

普通 MCP 客户端使用 `https://reader.example.com/mcp/<通用路径钥匙>`，并单独填写该身份的 Bearer 令牌。示例 ChatGPT 入口使用另一把 URL 钥匙，经 `https://mcp.example.com/mcp/<专用路径钥匙>` 映射到服务端的 `004` 身份，客户端 Auth 选 None。两种钥匙和身份令牌必须分别生成；不要把真实值提交到仓库。

源码中只保留示例域名和测试身份，不含生产书籍、划线、身份凭证、管理员口令、路径钥匙、服务器 IP 或部署配置。部署前替换 `*.example.com`，并在服务器上生成凭证。`004` 只是专用 URL 网关的示例身份名；若使用该网关，需先在令牌管理页创建此身份。

隔离测试：在 Linux 上安装 `core/requirements-mcp.txt` 后运行 `python3 core/selftest-cloud.py`、`python3 core/selftest-import.py`、`python3 token-mcp/selftest.py`，可按需运行原编码与 EPUB 转 TXT 自测。测试只使用临时书库和临时身份文件，不会读取生产数据。

阅读页先验证已有身份令牌，通过后才启动阅读器；MCP 和读写权限仍按原身份鉴权。书库页面支持按书名或文件名即时筛选，也支持导入 TXT 和 EPUB。服务端检查文件类型及内容，TXT 自动识别 UTF-8、带 BOM 的 UTF-16/UTF-32、GB18030 和 Big5；EPUB 按 spine 提取正文并保留原生目录映射，以 UTF-8 TXT 入库。仅主人身份可以上传。TXT 上传上限64MiB，EPUB 压缩包上限12MiB（解压总量32MiB、单资源4MiB）；导入串行，转换超时25秒，重名书籍返回 409，不会覆盖已有阅读进度或批注。

2026-10-15 增量：同一共享书库的身份可按书查询彼此的阅读进度；书库抽屉中的「共读进度」显示当前书的记录，「总览」跨书显示每个身份最近一次保存的进度。总览只读，不改变续读点。前端只有在用户明确点击「将当前位置设为续读点」时才保存进度，临时查看搜索结果或他人进度不会写盘。`GET /api/reading-progress/latest` 提供聚合查询，MCP 提供 `get_reading_progress` 与 `list_reading_progress`。旧版 MCP `update_progress` 仍可调用；直接写入 HTTP `/api/progress` 的客户端需要携带正文版本和预期修订号。详见部署文档。

公开版按真实身份 ID 显示共读成员，例如 `user`、`reader01`、`agent01`，不内置任何部署者的个人昵称映射。颜色仅用于展示，数据归属由服务端鉴权确认的 ID 决定；修改显示方式不改写身份、令牌、进度、划线或批注。

当前 TTS 在未配置服务端供应商时使用设备浏览器的语音合成；可选服务端在线合成按段调用，音频只在进程内作有限临时缓存。本包不含本地语音模型，也不附带供应商密钥。

2026-10-16 Kindle 扩展：安装后，主人在书库抽屉底部生成十分钟、一次性配对链接；Kindle 确认后获得 90 天的独立 HTTPS 设备 Cookie。主人可撤销设备，手机和 MCP 原有令牌不变。设备会话保存在 `core/data/kindle_auth.json`，首次配对时创建，不修改现有书籍、进度或批注。`/kindle` 轻量页无需 JavaScript，触屏点按翻页，接续 `user` 的共享进度。正文按页读取，服务端仅缓存最多两本书的稀疏定位索引。隔离测试与安装步骤见扩展包的 `README.md`。

Kindle 阅读页现在将正文大小与每页字数绑定：常规字 18px／440 字、大字 20px／340 字、特大字 22px／280 字。用户在 KPW6 真机确认常规字号下 440 字合适；放大时同步缩短页长，避免文字落到屏幕之外。页首控件和「暂未同步」提示保持原尺寸和紧凑布局。切换档位仅改变排版，不保存阅读进度；服务端分页按原文连续定位。若从 Kindle 打开完整阅读页，该页会显示无需 JavaScript 的「返回 Kindle 阅读」入口；临时的 `full=1` 参数也会在原阅读器脚本运行时清除，刷新后能回到 Kindle 页。

当 Kindle 与另一台设备同时使用同一身份阅读，且另一台设备先保存了进度时，Kindle 不再反复中断翻页或覆盖对方的续读点。它会进入「暂未同步」状态，仍可在本机继续翻页；暂停期间不写共享进度。其他设备停用后，读者可点「同步此处进度」明确将 Kindle 当前页设为共享续读点。每次同步仍检查服务端最新修订号。
